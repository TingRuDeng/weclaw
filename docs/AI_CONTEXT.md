# WeClaw AI 上下文

## Project Snapshot
- 仓库类型：单一 Go 仓库，不是 coordination directory。
- Go 模块：`github.com/fastclaw-ai/weclaw`，以 `main.go` 和 `cmd/root.go` 进入 CLI。
- 产品定位：把微信个人号和飞书消息接入 AI Agent，业务层通过 `platform` 抽象隔离平台差异。
- 发布目标：`scripts/release.sh` 与 CI 只构建和上传 `darwin/arm64`、`linux/amd64`，本机安装必须走 `weclaw update`。发布门禁同时验证一键安装脚本，测试只能使用隔离的伪命令环境。GitHub Release 是版本和构建权威；公开并验证后，`scripts/mirror_gitee_release.sh` 才通过外部 `GITEE_TOKEN` 把同一 main/tag、两项正式二进制的确定性 `.gz` 表示和原始 `checksums.txt` 镜像到 Gitee，并通过 `attach_files` 端点核对最终附件名称和数量，不再重复回下载镜像资产。安装器和更新器在 GitHub、Gitee 上都只支持这两个正式目标；Gitee 二进制附件执行有大小上限的解压，完整性仍以 GitHub 权威 `checksums.txt` 中的原始文件名为准。镜像脚本必须复用已有 Release、跳过已存在附件并为 curl 传输设置上限；`.github/workflows/mirror-gitee.yml` 只从既有 GitHub Release 下载权威资产，用于失败后的幂等续传。镜像失败不得清理已提交的 GitHub Release，但必须让发布任务可观察地失败。`.github/workflows/release.yml` 只负责从 `main` 调用该权威脚本，不得复制一套较弱的测试、构建或 Release 逻辑。发布入口先统一配置持久化 `GOCACHE`：`WECLAW_GOCACHE` 优先，其次保留调用方显式导出的 `GOCACHE`；本机 Darwin 数据盘共享根目录存在时使用项目专属缓存，其他主机回退到 `go env GOCACHE`。

## Core Directories

- `cmd/`：CLI 命令、启动、停止、更新、重启保护、Companion 和发布相关入口；更新后重启与手动重启必须在停止旧服务前复用启动预检。`weclaw restart` 默认只读检查冲突 Codex Host；只有显式 `--stop-conflicting-codex-hosts` 才能停止身份验证通过的 official daemon、Codex App 私有 Host 或 WeClaw-managed Host。停止前必须完成 PID、PGID、UID、启动时间、命令哈希及 protected metadata/lifecycle 复核；任一漂移或未知进程均失败关闭。`--force` 只作用于 WeClaw 自身任务。WeClaw 未运行时同样通过 Agent 的离线受控入口执行显式停止，不按进程名清理、不删除 lock/journal/Codex 数据目录。
- `config/`：配置结构、默认值、Agent 探测、工作目录白名单、平台/机器人用户白名单与旧配置兼容告警和 API 安全校验。
- `agent/`：统一 Agent 接口与各类 runtime；`codexauth/`：按 shared-host namespace 隔离的 OAuth profile、系统凭据库/显式文件后端、安全文件与跨进程事务锁。
- `platform/` 提供跨平台消息与回复抽象；`messaging/` 负责命令、会话、审批、结构化进展、任务状态、终态 outbox 和 Agent 调用。
- `observability/`：端到端 Trace 上下文、固定字段事件、轮转 JSONL 存储、受保护查询和 Codex 线协议脱敏录制。
- `feishu/` 负责飞书事件与交互；`wechat/`、`ilink/` 负责微信个人号接入、replier、token 和 monitor。
- `api/` 提供本机 HTTP API；`web/` 提供配置界面；`docs/`、`tasks/` 保存上下文、当前任务和长期 lessons。

## High-Risk Areas

- 飞书真实发送者身份和 session routing 必须分离；`platform.IncomingMessage.Route` 是一等会话路由，`feishu_session_key` metadata 仅作卡片载荷与旧调用兼容，迁移期必须双写双读。路由不得替代真实 `UserID` 或发送目标。
- 飞书会话按聊天窗口聚合：DM 使用 `feishu:<tenant>:dm:<chatID>:<senderOpenID>`，群聊使用 `feishu:<tenant>:group:<chatID>`；回复串 / 话题不再生成独立 route。
- 飞书多项目入口通过 `platforms.feishu.bots[]` 配置多个机器人；每个 bot 的凭证按 `weclaw feishu login --name <bot>` 或 `weclaw feishu bootstrap --name <bot>` 保存，`app_secret` 不得写入 `config.json`。飞书与微信账号凭据、微信主动发送所需的 `context_token` 统一通过 `internal/securefile` 读写：目录和文件最终固定为 `0700/0600`、原子替换；读取凭证前可自动收紧当前用户拥有的真实目录和普通文件权限，仍拒绝符号链接、异常 owner、非目录/非普通文件和无法安全修复的状态。损坏或不可读的 token 状态必须阻止对应 adapter 启动，不能静默当成空状态覆盖。共享同一 `WECLAW_HOME` 的微信凭据与 `context_token` 读改写事务统一通过 `internal/accountstore` 的进程内门禁和 Unix advisory lock 串行化；固定的 `accounts/.write.lock` 必须持久保留，不能删除或原子替换。
- `weclaw feishu bootstrap` 只负责首次配置向导：保存凭证、更新 `bots[]`、提示可用 `lark-cli` 做权限/事件诊断；飞书运行时仍使用内置 SDK 长连接，不依赖 `lark-cli`。
- 飞书显式启用时必须配置非空 `bots[]`；缺失 bot 应在 `config.Validate` 阶段 fail-fast，不应等到平台启动阶段才失败。
- 飞书最小权限应覆盖单聊入站、群聊 @ 入站、读取消息资源、发消息、资源、会话、CardKit 和机器人菜单：`im:message.p2p_msg:readonly`、`im:message.group_at_msg:readonly`、`im:message.group_at_msg.include_bot:readonly`、`im:message:readonly`、`im:message:send_as_bot`、`im:resource`、`im:chat`、`cardkit:card:read`、`cardkit:card:write`、`application:bot.basic_info:read`、`application:bot.menu:write`；`user` scopes 可为空。下载图片或文件需要 `im:message:readonly`、`im:message.history:readonly` 或 `im:message` 中至少一个，只有入站事件权限仍会收到消息但无法获取资源。
- 飞书 bot 的 `allowed_users`、`default_agent` 和 `progress` 按 `app_id` 隔离；`allowed_users` 支持应用级 `open_id` 和同开发商下稳定的 `union_id`，多机器人优先配置 `union_id`；新增、删除 bot 或修改 `app_id` 属于平台拓扑变化，需要重启。
- 飞书未授权入站身份会在访问控制前写入 `~/.weclaw/feishu-identities.json`，但不会自动放行；当前机器人 `allowed_users` 中的身份可在该机器人私聊通过 `/feishu users pending/list/approve` 确认后写入 `config.json`，本地只读查看使用 `weclaw feishu users pending/list`。远程命令必须固定作用于入站 `account_id`，本地多机器人写操作必须显式指定 `--bot`，不得跨机器人串权。
- `/progress` 从飞书入口触发时必须按当前 `account_id` 写入账号级配置；只有 Registry 按当前机器人 `allowed_users` 签发的账号级授权能力可以修改，未授权身份仍在平台入口默认拒绝。广播、Codex 会话切换和共享 host 任务 watcher 也必须读取账号级进度配置。Agent 到 messaging 使用 `agent.ProgressEvent` 传递 kind/state/id/path/sequence，旧字符串 Agent 只能在兼容边界包装；`Handler.tasks` 中的 `taskService.active` 持有活动任务索引，`activeAgentTask.view` 通过纯 reducer 保存唯一任务视图。原生 stream 任务卡的 `stream_timeline_limit` 默认 `0`，表示不设置 WeClaw 条数上限；正数表示只保留最近 N 条，负数配置必须拒绝。该字段按全局、Agent、平台、飞书账号四层合并并允许显式零覆盖；`max_progress_messages` 仍只限制非 stream 消息。stream 时间线条目包括按稳定 ID 语义合并的计划、工具和文件摘要，以及 Codex 明确标记为 `agentMessage.phase=commentary` 的用户可见消息；不包括 `commandExecution` 生命周期、原始协议事件、推理、逐 token、命令输出、工具日志或最终回答。同一语义阶段的运行/完成事件按稳定 ID 原位更新。`ProgressKindCommentary` 必须按来源顺序以完整正文累计进时间线并参与条数限制和自动续卡，不按 180 字符裁剪；Claude 的 `ProgressKindMessage` 继续只更新独立“当前说明”区域、推进事件水位且不占时间线，单条按 180 字符收敛。飞书任务卡在第一条有效非命令进度到达前，正文只能显示 `思考中.....`，定时心跳不得用等待、连接或阶段提示覆盖；Codex commentary、Claude message、计划、文件或工具摘要任一到达后，就在唯一 `main_content` 中默认实时展示当前分段最近 5 条语义合并进度，点击底部“展开完整进度”后同一区域切换为本分段完整时间线，展开期间后续事件继续追加或按稳定 ID 原位更新，点击“收起完整进度”后回到最新 5 条。预览只从 `stream_timeline_limit` 实际保留的当前分段时间线派生，不新增长期记录上限；不得重新渲染顶部预览和下方完整进度两个区域。预览和完整正文都只在底部保留一次活跃提示，终态必须移除并自动收起。命令、内部推理、状态心跳和审批事件不能解除等待态；审批仍使用独立交互与记录区域。`/ps` 读取同一 reducer 的最近 display text，旧字符串 Agent 和非 stream 平台保持原有兼容行为。飞书在每次更新及初始卡创建前按完整展开卡片 JSON 的保守字节软上限预检；预计超限时旧卡保留并冻结当前段，先持久化新卡恢复引用，再把审批绑定、后续进展和终态迁移到带连续段号的新卡，不能等待 API 拒绝、用五条预览绕过容量检查或静默截断。任务结束时最新卡只把标题或状态收敛为完成、失败或停止并关闭流式状态，必须保留当前分段、审批、时间线和当前说明；这些内容都不存在时只保留对应终态，不合成“没有结构化进度”类正文。Codex App Server 的 `turn/plan/updated` 以及 `fileChange`、`mcpToolCall`、`dynamicToolCall` 生命周期必须转换为安全摘要；`commandExecution` 生命周期不投影到进度卡，真正需要用户处理的命令审批仍通过独立 approval 事件展示。命令输出、工具参数、结果、diff 和逐 token 增量不得进入卡片，`final_answer` 和未知阶段只参与最终回答组装。真正需要用户处理的其他权限审批和补充信息仍必须明确展示；内部输出 delta、patch delta、审批审查、guardian 和传输 warning 只在协议层消费或脱敏记录。终态水位线之后的旧 sequence 或晚到 watcher 不得覆盖终态。Codex 窗口切回仍在运行的任务时，只在 frontend binding 真实变化后于消息底部重建任务卡，并以 reducer 最新快照初始化；旧卡进入“已转移”且停止流式，后续进展和终态只能写当前卡，重复选择同一绑定不得重复建卡。独立任务卡可用时，会话切换结果只确认工作空间、模型配置和任务卡位置，不得重复展示任务正文、当前进展或终态回传说明；无任务卡的文本平台继续保留完整摘要。飞书任务卡 registry、durable stream reference 与终态 checkpoint 必须同时保存预览、完整正文和展开状态；服务重启后继续按当前状态更新同一个 `main_content`，旧引用缺少预览时降级显示完整正文。按钮回调只按任务卡 ID 和单调 sequence 更新原 CardKit 卡，不得进入 Agent 命令路由；状态失效或更新失败必须提示用户。普通进度只更新稳定正文组件，不全量重建卡片，因此不能重置用户选择；完成、失败、停止和已转移卡默认收起。Codex 活动 - `messaging/codex_session_acquire.go:acquireCodexSessionWithBindingLocked` 先准备目标 thread 的 provider 兼容状态，再以 LP1 提交当前 route binding 和 `preparing` follower。接管成功必须继续确认当前 Host generation、读取权威历史，并在 active turn 上先创建原生进度卡、回放已有进度并完成 exact-turn observer handshake；只有 `commitFollowerAttachReady` 对精确 binding revision、attach revision、turn ID 和 runtime generation 的 LP2 CAS 成功后，才能返回接管成功、放行普通写入或回写原飞书结果卡。任一步失败都保留同一 revision 的 `preparing` 意图供后台幂等恢复，不能显示“已切换并绑定”、误投旧会话或启动第二 Host。Desktop `no-client-found` 只是私有 App Host 兼容路径的 follower 状态，不能改变 official daemon authority。历史 Codex thread 的 `model_provider` 不是续写权威；当前 Host 对目标 workspace 生效的 provider 才是权威，绑定前和 writer lease 前都必须复核，不同时继续使用已有 fail-closed 迁移事务。
- `agent/codex_runtime_lease.go` 只把当前 Host 级权威运行态（`weclaw` 或 `desktop`）视为可写，同一 thread 同时只允许一个新 turn writer lease；route、窗口或旧 owner revision 不参与生产多 frontend 写入授权。已有活动 turn 时，其他前端的普通输入通过 `turn/steer` 直接进入同一 turn，不创建私有 pending queue 或第二 lease。全局输入顺序从 app-server 接受请求开始；Desktop/CLI 尚未发送的 queued follow-up 只是客户端草稿。飞书绑定 active thread 时必须先回填权威快照并持续观察；active turn 输入携带 expected turn ID 直接 steer，空闲时才开始新 turn。app-server 允许进度、审批甚至终态早于 `turn/start` RPC 响应到达；collector 必须立即处理非终态和交互，避免服务端等待审批形成死锁，但终态返回必须等启动结果和 `OnTurnStarted` 生命周期提交完成，不能让迟到的 accept 因任务已清理而失败。turn 接受后观察通道断线必须保留 uncertain lease，只有权威 Host 的终态证据才能释放；非权威 Host 的晚到广播不得生成事件、改写 binding 或清除 lease。
- Codex 会话绑定和 watcher 恢复不得把完整 rollout 历史装入单条 ACP 响应：`thread/resume` 固定发送 `excludeTurns: true`，状态探测使用 `thread/read includeTurns:false` 后只读取 `thread/turns/list itemsView:notLoaded` 的最近一页。需要回放时先按 64 条一页分页查找精确目标 turn，优先通过 `thread/items/list` 按 32 条一页顺序加载该 turn 的 items；若当前 official daemon 明确返回该方法不受支持，则复用命中元数据页的 cursor，以 `thread/turns/list itemsView:full` 只重新读取目标所在页，其他错误不得触发降级。指定 turn 不存在、cursor 重复或 item 属于其他 turn 都必须失败关闭，不能落到后续 turn 或处理旧审批。每页响应仍受 ACP Scanner 64 MiB 单帧上限约束；异常超限必须保留 `ErrACPFrameTooLarge` 错误链并向会话绑定入口返回明确的 Codex CLI 更新提示，不能只显示通用“绑定失败”。
- `/cx` 是 Codex 会话命令专用命名空间，未知子命令统一返回 `/cx help`；Codex 消息使用 `/codex <内容>` 或 `@cx <内容>`。`/cx owner` 及其旧参数已删除；`/cx release` 只解除当前 route 的 durable binding、冻结活动卡并停止该 route 的进度、审批、问答和终态投递，不得 interrupt、stop 或重启 Host；`/cx status` 正常态只紧凑展示工作空间短名、会话、任务、账号标签和运行状态，Desktop 模式显示 `Codex App`。`/cx app`、`/cx cli`、`/cx attach`、`/cx detach` 继续拒绝从消息端启动本机进程；本机终端入口是 `weclaw codex cli`。旧 Codex Companion 和原生 `type: cli` 配置迁移到共享 ACP app-server，`codex exec` 独立会话模式明确停用。App Host 的 follower IPC 支持已有 thread 的历史、turn、steer、interrupt、审批、用户输入、thread settings 和按 connection epoch 同步的 queued follow-up 草稿；草稿不能生成 writer lease、WeClaw pending task 或已接受输入。Desktop follower 不暴露 thread/start、archive、model/list、账号与额度接口，因此这些操作必须明确提示在 Codex App 执行，`/cx new` 失败时不得删除当前 binding。`/model`、`/reasoning` 在已有 App thread 上使用 `thread-follower-update-thread-settings`，共享 Host 继续使用 `thread/settings/update`；未知能力不得静默降级。`/cx rename current|<编号> <名称>` 只通过 shared app-server 的 `thread/name/set` 修改 Agent 全局 thread 名称，并以第二次 `thread/read.name` 精确读回为成功依据；Desktop follower 没有该写能力时提示在 Codex App 内执行，禁止为重命名启动第二个 Host。消息层在 binding 锁内解析可访问且未隐藏的目标，再按 thread control 和 writer 门禁拒绝 active/unknown 任务；RPC 已发送但响应或读回无法确认时保留全部 binding 并返回未知结果，审计只记录脱敏 thread ID，不记录名称。Desktop pending approval 的五分钟等待是权威复核周期，不是默认拒绝期限：每次复核必须调用带 revision 屏障的完整 history 刷新，并用原 turn ID 与 request ID 判定；request 仍存在时续期且不调用 responder，request 消失但原 turn 仍 active 时视为已由 App 或其他前端处理，原 turn terminal/rollover 时禁止旧 turn steer，刷新或投影不确定时保持 pending、保留 binding 并失败关闭。普通消息、审批文本、短码和卡片动作在提交决定前都必须复核，`Request not found` 竞态按并发已处理收敛；飞书原审批卡只更新为“已在 Codex App 处理”或“任务已经结束”，展示失败不改变审批真值。Desktop 已明确返回的错误不得包装为 `ErrCodexDesktopDeliveryUnknown`；只有写后断线或响应超时保留交付未知语义。

- Claude ACP 复用通用后台任务队列：每个活动任务最多暂存一条同 route 消息，失败后仍自动续跑；`/cancel` 撤回暂存，`/stop` 按当前窗口 Agent 停止，`/guide` 对 Claude 明确不支持。
- 飞书显式绑定 official daemon thread 时会持久化 route follower；idle→active 事件立即唤醒调和，周期快照只负责断线和漏事件恢复。active attach 必须先回放当前 turn 已有的可见自然语言进度、创建原生任务卡并完成 exact-turn observer readiness，再持续接收增量；命令、原始工具日志和最终回答不写入进度回放。多个 ready route 同时观察同一 turn，进度、审批/问答展示和终态按 route 独立投递；`agent/codex_interaction_broker.go` 按 `(thread, turn, request)` 串行唯一决策，`serverRequest/resolved` 会让其他 observer 幂等收敛。重启先在 worker 启动前 hold guarded terminal 及其 pending supersede，然后按 `host_authority -> history_snapshot -> interaction_replay -> observer_ready -> outbox_delivery` 恢复；`startupHeld` 在 due 调度、timer 计算和最终 attempt 三层阻止旧卡或终态提前投递。`/cx release` 先持久化 route tombstone 与无终态 detach 补偿，持久化失败保留绑定；成功后才停止当前 observer，不 interrupt turn、不重启 Host、不影响其他 route，且不再收到未 claim 的交互或终态。
- 运行中任务登记在 `Handler.tasks` 所有的 `taskService.active` 索引；`stop`、`restart` 和 `update --restart` 必须先持有 `state/codex-frontends.lock` 排他租约，并通过 loopback `/api/runtime/restart/prepare` 原子关闭 admission、排空任务和停止受管 Codex Host。普通模式遇到 active task 时恢复 admission 并拒绝，强制排空才取消普通任务并有界等待终态；对 durable Codex follower 或同一进程中的共享 turn observer，强制排空只能解除本进程 observer 并保留恢复项，不能 interrupt 仍由 App/CLI 继续的 active turn，因而后续全局 idle 门禁仍会拒绝 Host 停止。受控 `weclaw codex cli` 在完整 TUI 生命周期持有共享租约；App 进程/IPC、任意 writer lease、active/unknown thread 或 Host 身份存在时 Host 事务失败关闭，且强制排空不得绕过。App 必须由用户完整退出；WeClaw 只通过受保护 IPC 和同 UID 主进程名做保守存在性探测，不会按进程名终止 App。验证通过后只停止带 PID/UID/启动时间/命令/generation 身份的 official daemon 或 managed Host。CLI `weclaw stop` 只有在事务成功后才向服务发送 `SIGTERM`，事务或外层停止失败时执行补偿并保持旧服务可用；服务直接收到 `SIGINT`/`SIGTERM` 或消息桥自行退出时也先尝试同一事务，安全门禁不满足则保留 Host、记录原因并服从外部停止。systemd unit 必须使用 `KillMode=process`，确保停止信号只发送给 WeClaw 主进程而不绕过协调事务触碰同 cgroup 的 Host。`state/runtime-restart.json` 在 Host 停止前持久化恢复意图；后续服务在平台注册前启动唯一 Host 并验证 generation 已变化，如果旧 generation 仍在则先安全替换，失败保持不可写。持久化事务存在时新的受控 CLI 也必须失败关闭。PATH 二进制已经更新但运行中服务尚未更新时，HTTP 404 是能力协商结果，不是 JSON：CLI 必须读取运行态版本、在任何进程变更前返回 `stop` → `start` → `restart` 的一次性迁移指引，并且不得对未创建的事务发送 DELETE 补偿或自动降级为不轮换 Host 的普通停止或重启。systemd 运行态必须委派固定 `weclaw.service`，不得停止后另起后台 daemon；普通 `weclaw update` 不得隐式重启。
- 微信 / 飞书远程管理命令由 `messaging/admin_commands.go` 执行 WeClaw 自身命令，不应进入 Codex / Claude；必须只信任 `platform.Registry` 按当前 platform/account/identity 的 `allowed_users` 签发的不可伪造授权能力；所有已授权身份具有相同管理能力，远程身份管理只能作用于入站机器人账号。旧顶层 `admin_users` 只为 JSON round-trip 兼容而保留，运行时告警并忽略，不自动迁移或扩大授权；Web 配置视图不得展示、接受或修改它。飞书身份可使用账号级 `open_id`，跨同开发商应用时优先使用稳定 `union_id`，`/update` 与 `/restart` 还必须在可证明的私聊窗口执行。支持流式卡片的平台执行 `/update` 时必须在同一卡片内从版本检查收敛到“已是最新版本 / 更新成功 / 失败”终态；`/restart` 必须在旧进程保存 CardKit 卡片引用后才释放延迟启动，启动失败时由仍在运行的旧进程删除待完成记录并把原卡收敛为失败，新进程确认恢复后才回写同卡成功终态，直接更新失败才把固定 checkpoint 交给 terminal outbox 重试。不支持流式卡片的平台降级为先回复后台受理、结束后另发最终结果。`/update` 摘要必须识别 CLI 当前使用的中文版本输出。群聊 `/mode yolo` 按真实操作者和 route 的组合键隔离，不能让同群其他成员继承自动审批；切换时先按既有幂等门禁放行该范围内的 pending approval，再把已发飞书审批卡更新为无按钮的自动批准终态并写入任务卡。CardKit 更新失败只能告警和审计，不得撤销或重复提交 Agent 审批；后续 YOLO 审批不再弹独立审批卡，有任务卡时只追加自动批准记录。
- 微信同一条入站消息触发多次回复时，`wechat.Replier` 必须为后续 `SendText` 生成新的 `client_id`，避免微信端把结果消息按重复消息去重。外部 `ILinkBotID` 写入凭据或 context token 路径前必须统一通过 `ilink.NormalizeAccountID` 编码，不能把 `/`、`\\`、绝对路径或 Unicode 原文直接交给 `filepath.Join`；旧版兼容映射发生文件名碰撞时，保存和加载都必须失败关闭。Web 扫码登录同一服务只允许一个 active poll，新登录必须取消并终态化旧会话，晚到回调不得保存旧凭据或覆盖新状态。
- Agent `permission_level` 省略时等同 `default`；显式配置只接受 `default`、`auto_review`、`full_access`，分别映射 Codex `approvalPolicy`、`sandboxMode` 与 `approvalsReviewer`，旧值必须 fail-fast。`weclaw config permission --agent <name> --level <level>` 会清空三个高级覆盖字段，运行中 Agent 必须重启后生效。`auto_review` 仍是 `workspace-write + on-request`，只把 reviewer 交给 Codex，WeClaw 不会把审查失败转成允许；`full_access` 仍只拥有运行 WeClaw 的操作系统用户本来可访问的范围。聊天 `/mode yolo` 只是当前进程内按操作者与 route 隔离的审批自动允许，不持久化、不改变 sandbox 或权限档位。`codex_host_mode` 只接受 `auto`、`daemon`、`managed`；显式 daemon 禁止自定义 socket 和 `run_as_user`。原生 Codex shared app-server 规范化后默认写入 `codex_auto_update: incompatible`，但只有上游明确报告 schema/version 不兼容且没有 writer lease 时，兼容 managed Host 才能持有生命周期锁调用官方 `codex update`。通用 SQLite 初始化错误、锁争用、损坏、socket 就绪超时、调用方取消、普通进程退出和连接错误不得触发更新；官方 daemon 模式也不得由 WeClaw 更新。更新前后版本必须可验证且真实变化，失败、版本未变或更新后仍无法启动都保持 fail-closed。显式 `off` 永久关闭该行为。
- Web 配置保存必须保留 Agent 的 Codex 权限字段、共享意图、Host 模式、共享 socket 和更新策略：`permission_level`、`approval_policy`、`approval_reviewer`、`sandbox_mode`、`codex_multi_frontend`、`codex_host_mode`、`app_server_socket`、`codex_auto_update`。所有运行期配置读改写必须通过带进程内与跨进程锁的 `config.Update` 重新读取最新快照；Web 配置视图必须携带版本指纹，旧页面保存时返回冲突，不能覆盖消息端或 CLI 刚提交的 `allowed_users`。
- `api_addr` 监听非 loopback 地址时必须配置 `api_token`；loopback 地址允许留空，但 `weclaw doctor` 必须告警本机其他进程可调用管理接口，不能显示为安全通过。
- 发布后本机更新必须走 GitHub 权威 Release，或在 `darwin/arm64`、`linux/amd64` 上走 Gitee 镜像，并由 `weclaw update` 校验，不要手工覆盖二进制。`update_source`/`WECLAW_UPDATE_SOURCE`/`--source` 支持 `auto`、`github`、`gitee`，命令行优先于环境覆盖后的配置；`auto` 只允许对网络、TLS、超时和 5xx 换源，4xx、非法 tag、摘要缺失/重复/不匹配必须失败关闭，稳定版本不得降级。普通 `weclaw update` 在已是最新版时不得启动 Claude ACP 预检；实际安装新版本或显式 `update --restart` 才执行启动预检。安装新版本时必须保留临时旧二进制直到完成边界提交，预检失败必须恢复旧二进制；`update --restart` 的安全检查、停止或新版本启动失败也必须恢复旧二进制，旧服务已停止则重新启动旧版本，恢复失败必须同时保留原始错误和回滚错误。Codex 用户可见消息投影以显式 `phase=commentary` 为最高优先级；为兼容真实运行时省略 `phase` 的情况，受控 turn 与外部 watcher 必须共同延迟一条已完成消息。后续另一条消息、计划、文件、工具、审批或不含正文的命令活动证明 turn 仍在继续时，上一条才转换为 `ProgressKindCommentary`；正常 `turn/completed` 前仍待判定的最后一条只作为最终回答。命令活动信号不得携带命令、输出或 `ProgressEvent`，也不得解除“命令不展示”的边界。同一消息 ID 的重复快照只更新待判定正文，不得重复追加。
